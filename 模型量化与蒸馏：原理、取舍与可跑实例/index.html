    模型量化与蒸馏：原理、取舍与可跑实例¶

    这篇只讲一件事：怎么把一个“大模型”变成“更小、更省、更好部署”的模型。 量化解决的是表示精度，蒸馏解决的是能力迁移。

    一、先给结论¶

    如果你要把模型真正落到生产里，通常有三条路：

    1. 直接量化：最快，最省事，适合先把显存和延迟压下来。
    2. 先蒸馏，再量化：最常见的工程路线，先保住效果，再压缩体积。
    3. 量化 + 蒸馏 + 微调：最稳，但成本也最高，适合要长期服务的模型。

    粗暴一点说：

    • 量化让模型“少占地方”
    • 蒸馏让小模型“更像大模型”

    如果只记一句：

    量化是压缩数值表示，蒸馏是压缩行为分布。

    二、量化到底在做什么¶

    量化的核心，是把高精度参数换成低精度表示。

    原本的浮点数：

    fp32 / fp16 / bf16

    可以变成：

    int8 / int4 / 其他低比特格式

    常见映射可以写成：

    x_q = round(x / scale) + zero_point
x  ≈ scale * (x_q - zero_point)

    量化之后，模型通常会获得两个好处：

    • 参数占用更小
    • 推理更省内存带宽

    但代价也很直接：

    • 精度会掉一点
    • 有些算子不一定都能被高效量化
    • 不同硬件对量化友好程度不一样

    2.1 常见量化类型¶

    PTQ，Post-Training Quantization

    • 训练完再量化
    • 成本最低
    • 适合快速上线

    QAT，Quantization-Aware Training

    • 训练时模拟量化误差
    • 效果通常更稳
    • 训练成本更高

    Dynamic Quantization

    • 常见于 CPU 上的线性层
    • 权重先量化，激活按运行时处理
    • 很适合文本分类、小型 MLP、部分 Transformer 推理

    Static Quantization

    • 需要校准数据
    • 对卷积网络、固定输入分布场景更合适
    • 需要更完整的量化流程

    LLM 常见权重量化

    • 8-bit / 4-bit weight-only
    • AWQ / GPTQ / bitsandbytes 一类方案
    • 更偏大模型部署

    PyTorch 官方文档把动态量化、静态量化和 QAT 都归在量化工具链里；Hugging Face 的 Transformers/Accelerate 文档则更常见于 8-bit / 4-bit LLM 部署。

    三、蒸馏到底在做什么¶

    蒸馏的核心，是让小模型学大模型的输出分布。

    大模型叫 teacher，小模型叫 student。

    蒸馏不只是学“答案对不对”，而是学：

    • 哪些类别很接近
    • 哪些判断边界更平滑
    • 哪些错误代价更低

    经典蒸馏损失通常长这样：

    L = alpha * CE(y, student_logits)
  + (1 - alpha) * T^2 * KL(softmax(teacher_logits / T),
                           softmax(student_logits / T))

    这里：

    • CE 是硬标签损失
    • KL 是软标签对齐
    • T 是温度
    • alpha 控制硬标签和软标签的权重

    3.1 为什么温度有用¶

    温度越高，softmax 分布越“平”。

    这会把 teacher 的“暗知识”摊开：

    • 第一名类别不再一家独大
    • 次优类别的相对关系更明显
    • student 更容易学到“为什么像”

    3.2 蒸馏常见变体¶

    • logits distillation：最常见
    • feature distillation：对齐中间层特征
    • sequence distillation：文本生成里常见
    • data-free distillation：没有原始数据时的变体

    3.3 什么时候适合蒸馏¶

    适合：

    • 你已经有一个强 teacher
    • 你希望 student 轻量但别太掉点
    • 你愿意为训练多花一点时间

    不适合：

    • 你连 teacher 都不稳定
    • 任务本身很简单
    • 数据分布变化太快，蒸馏后很快失效

    四、量化和蒸馏怎么选¶

    4.1 先选谁¶

    如果目标是快速部署，先量化。

    如果目标是长期压缩，先蒸馏，再量化。

    4.2 经验判断¶

    场景 更推荐
    只想先降显存 量化
    线上延迟和显存都紧 蒸馏 + 量化
    teacher 很强，student 要尽量接近 蒸馏
    模型已经很小 可能都不值得做

    4.3 一条实用路线¶

    teacher 训练好
  -> 用 teacher 生成软标签
  -> 蒸馏出 student
  -> 对 student 做量化
  -> 评估精度 / 延迟 / 体积

    这条路线最像真实工程。

    五、一个可跑的最小实例¶

    下面这个例子只依赖 torch，可以在 CPU 上跑完。

    它会做四件事：

    1. 造一个简单的二维分类数据集
    2. 训练一个较大的 teacher
    3. 训练一个较小的 student baseline
    4. 训练一个蒸馏 student，再对它做动态量化

    5.1 安装¶

    pip install torch

    5.2 完整脚本¶

    把下面代码保存成 distill_quant_demo.py 直接运行即可。

    如果你的 PyTorch 打出 torch.ao.quantization 的弃用提醒，可以先忽略；这个最小例子仍然能正常跑通。

    import copy
import io
import time

import torch
import torch.nn as nn
import torch.nn.functional as F


torch.manual_seed(42)


def make_dataset(n=6000):
    x = torch.empty(n, 2).uniform_(-3.0, 3.0)
    logits = (
        1.4 * x[:, 0]
        - 0.8 * x[:, 1]
        + 0.7 * torch.sin(1.8 * x[:, 0])
        - 0.5 * x[:, 0] * x[:, 1]
    )
    y = (logits > 0).long()
    return x, y


class MLP(nn.Module):
    def __init__(self, hidden1, hidden2=None):
        super().__init__()
        hidden2 = hidden2 or hidden1
        self.net = nn.Sequential(
            nn.Linear(2, hidden1),
            nn.ReLU(),
            nn.Linear(hidden1, hidden2),
            nn.ReLU(),
            nn.Linear(hidden2, 2),
        )

    def forward(self, x):
        return self.net(x)


def accuracy(model, x, y):
    model.eval()
    with torch.no_grad():
        pred = model(x).argmax(dim=1)
        return (pred == y).float().mean().item()


def model_size_kb(model):
    buffer = io.BytesIO()
    torch.save(model.state_dict(), buffer)
    return buffer.tell() / 1024.0


def train_teacher(model, x, y, epochs=180, lr=0.01):
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for _ in range(epochs):
        logits = model(x)
        loss = F.cross_entropy(logits, y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model


def train_student_ce(model, x, y, epochs=140, lr=0.01):
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for _ in range(epochs):
        logits = model(x)
        loss = F.cross_entropy(logits, y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return model


def distill_loss(student_logits, teacher_logits, y, temperature=4.0, alpha=0.35):
    soft_teacher = F.softmax(teacher_logits / temperature, dim=1)
    soft_student = F.log_softmax(student_logits / temperature, dim=1)
    kd = F.kl_div(soft_student, soft_teacher, reduction="batchmean") * (temperature ** 2)
    hard = F.cross_entropy(student_logits, y)
    return alpha * hard + (1 - alpha) * kd


def train_student_kd(student, teacher, x, y, epochs=140, lr=0.01):
    opt = torch.optim.Adam(student.parameters(), lr=lr)
    teacher.eval()
    for _ in range(epochs):
        with torch.no_grad():
            teacher_logits = teacher(x)
        student_logits = student(x)
        loss = distill_loss(student_logits, teacher_logits, y)
        opt.zero_grad()
        loss.backward()
        opt.step()
    return student


def benchmark(model, x, runs=2000):
    model.eval()
    start = time.perf_counter()
    with torch.no_grad():
        for _ in range(runs):
            _ = model(x)
    return time.perf_counter() - start


def main():
    x, y = make_dataset()
    split = int(0.8 * len(x))
    x_train, y_train = x[:split], y[:split]
    x_test, y_test = x[split:], y[split:]

    teacher = MLP(128, 128)
    teacher = train_teacher(teacher, x_train, y_train)

    student_ce = MLP(32, 32)
    student_ce = train_student_ce(student_ce, x_train, y_train)

    student_kd = MLP(32, 32)
    student_kd = train_student_kd(student_kd, teacher, x_train, y_train)

    try:
        from torch.ao.quantization import quantize_dynamic
    except ImportError:
        from torch.quantization import quantize_dynamic

    quantized_student = quantize_dynamic(
        copy.deepcopy(student_kd).cpu().eval(),
        {nn.Linear},
        dtype=torch.qint8,
    )

    models = {
        "teacher": teacher,
        "student_ce": student_ce,
        "student_kd": student_kd,
        "student_kd_int8": quantized_student,
    }

    probe = x_test[:256]
    print("model,accuracy,size_kb,infer_ms")
    for name, model in models.items():
        acc = accuracy(model, x_test, y_test)
        size_kb = model_size_kb(model)
        elapsed = benchmark(model, probe)
        infer_ms = elapsed * 1000 / 2000
        print(f"{name},{acc:.4f},{size_kb:.1f},{infer_ms:.4f}")


if __name__ == "__main__":
    main()

    5.3 这段代码在做什么¶

    • teacher 负责学得更完整
    • student_ce 只靠硬标签训练，作为基线
    • student_kd 同时学硬标签和 teacher 的软分布
    • student_kd_int8 把蒸馏后的 student 再做动态量化

    5.4 你应该看什么结果¶

    跑完后会输出类似：

    model,accuracy,size_kb,infer_ms
teacher,0.98xx,xxx.x,xx.xxxx
student_ce,0.94xx,xx.x,xx.xxxx
student_kd,0.96xx,xx.x,xx.xxxx
student_kd_int8,0.95xx,xx.x,xx.xxxx

    重点不是具体数字，而是这个趋势：

    • student_kd 通常比 student_ce 更接近 teacher
    • quantized student 通常更省空间
    • 精度可能略掉一点，但通常还在可接受区间

    这个 toy example 很小，所以量化版本不一定更快，甚至可能略慢；这很正常。真实大模型或更大 batch 下，量化的收益通常会更明显。

    六、为什么这个例子有价值¶

    这个例子虽然小，但它把真实工程里的三件事都串起来了：

    1. teacher/student 结构
    2. KD 损失函数
    3. 量化后的部署收益

    这比单独讲一个概念更接近实际。

    因为真正的生产流程通常是：

    先让模型学会
再让模型变小
最后再把部署成本压下来

    七、真实项目里更常见的做法¶

    7.1 大模型推理¶

    如果你是在做 LLM 推理，常见路线是：

    • 先选 8-bit 或 4-bit 权重量化
    • 再看是否需要对任务数据做蒸馏
    • 最后根据精度回退到更高比特或更强 teacher

    7.2 分类 / 检索 / 轻量服务¶

    如果你是在做分类、检索、排序、小型生成服务：

    • 蒸馏通常更值
    • 动态量化通常很容易落地
    • 如果输入分布稳定，还可以考虑静态量化或 QAT

    7.3 训练成本很高的场景¶

    如果训练成本特别高，最好的策略通常不是反复重训，而是：

    1. 把 teacher 固化
    2. 用 teacher 产软标签
    3. 一次蒸馏多个 student 版本
    4. 在线选择最合适的压缩档位

    八、常见误区¶

    8.1 误区一：量化一定更快¶

    不一定。

    量化主要省内存，速度是否提升取决于：

    • 硬件
    • 算子支持
    • batch size
    • 模型结构

    8.2 误区二：蒸馏就是降维版训练¶

    不是。

    蒸馏是让 student 学 teacher 的“分布形状”，不是简单把模型缩小一圈。

    8.3 误区三：量化和蒸馏可以互相替代¶

    也不是。

    • 量化压的是数值表示
    • 蒸馏压的是行为表达

    它们更像两把不同的剪刀。

    九、落地建议¶

    如果你刚开始做模型压缩，我建议按这个顺序：

    1. 先跑一个 teacher baseline
    2. 再做 student 纯监督训练
    3. 再加蒸馏
    4. 最后对 student 做量化
    5. 记录精度、延迟、体积三项指标

    这比一上来就碰 4-bit 大模型更稳。
